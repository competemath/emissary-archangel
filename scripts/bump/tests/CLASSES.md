# Classes of bug the factory's tests guard

Each class below cost a production run (an hour and a half to three hours of runners) at least once. The tests listed do not check the instance that was found; they check the INVARIANT of the class on
random or enumerated inputs, so the next member of the class fails in CI instead. When something new breaks in production, find its class here (or add one), then add a pattern/scenario to the test
that guards it, never only a regression test of the one instance.

| class | invariant | where it is enforced | what it cost |
|---|---|---|---|
| **absence of evidence is not evidence of absence** | a build that completed built every target, with or without a `Built` line; a module is refused only on evidence; a build that built nothing never got going and is refused | `test_classes_verify.py` (random import graphs x random logs: Evidence, NeverGotGoing) | Navier 2026-10-20: 67 modules had no line, 676 importers refused with them; 2026-10-21: toolchain download failed, an empty cut reported as success |
| **closure** | whatever ships imports only what ships; whatever is refused takes its importers with it, exactly; verdict and cut use ONE notion of importer | `test_classes_verify.py` (Closure), `test_classes_compose.py` (Closed: random DAGs, failures, aliases; oracle written independently) | Navier: 72 modules refused for an import an aliased copy took with it, 971 with importers |
| **monotone** | more evidence never removes a verified module | `test_classes_verify.py` (Monotone) | |
| **log segments** | what is appended to a build log (the second build, a repair round) never changes what the first build proves; a repaired module is judged on its round | `test_classes_verify.py` (Segments) | Navier: the ending of the second build was taken for the first's |
| **edits preserve meaning** | the text edits (fork wrap, alias, repair) leave the declarations of every module as they were, for every Lean scoping construct | `edit_corpus.py` + `bundle-keep-tests.yml` (real Lean: each pattern built original, forked, aliased; fingerprints compared); `test_edit_corpus.py` (corpus well-formed, comment-aware) | Navier: bare names through a re-opened namespace (#83), `open _root_.X` on a namespace nothing imports (#85), `open N` of a namespace declared on both sides (found by the corpus before it cost a run) |
| **a name in two worlds** | a name the forked copy and the tree both declare is the fork's wherever a wrapped file opens its namespace; the tree's is hidden exactly where the tree's module is in the file's import closure (Lean refuses to hide a name that does not exist), and nowhere else; no other name is lost | `test_classes_fork_names.py` (a model of what each `open` makes visible, on random files and hide sets; `fork_hide` against a naive closure on random import DAGs; plan -> merge -> compose bytes), `edit_corpus.py` (real Lean: the `fork_and_tree_*` patterns, hide computed from the real fingerprints and files) | Navier recut 8: `Ambiguous term Coefficients`, 24 modules refused |
| **a command is one unit** | the physical lines of a command (an `open` of several lines: 66 of Navier's 73 wrapped modules) are kept as they were and nothing is ever put between them; what the edit adds follows the last line or is chained to it with `in`; a line of names continues only when it is more indented and holds no keyword | `test_classes_fork_names.py` (multi-line commands in the random files; the `open_ml` frame and visibility checks; mutants), `edit_corpus.py` (`fork_and_tree_same_name_multiline_open`, `…_in_the_second_line_of_an_open`, `multiline_open_with_nothing_shared`) | Navier recut 9: `Unknown constant`, 17 modules refused: a line inserted inside a two-line `open` made the second line part of a `hiding` clause |
| **the reader understands every scope** | the names a file declares are read right whatever opens its scopes: `section`, `public section`, `@[expose] public section`, `meta section`, a namespace left open at the end (the fork's); a wrongly read list produces false clashes (modules already in the tree dropped with their importers) and misses real ones | `test_classes_lean_names.py` (random nested scopes x every opener form x prose that looks like code, against an oracle; a forked file keeps its prefix) | Navier recut 10: 6 modules already in the tree were called clashes with lean-pool's forked copies, 12,707 theorems dropped |
| **the tree decides** | a module a text rule flags (it proves a record the tree already has, or seems to declare a name another library declares) goes with its importers when nothing in the tree checked it; when the tree built it and none of its checks refused it, it ships, and only the records the tree already has are left out of the manifest, counted; a module a tree check refused goes as any refused module | `test_classes_compose.py` (TheTreeDecides: random libraries x flags x tree failures; manifest, ledger and accounting; 5 mutants) | Navier recut 10: 16 modules (1,052 theorems) dropped on paper, 5,875 theorems of importers with them |
| **edits are reproducible** | what the tree built is byte for byte what ships; an edit planned on the bytes of one stage is made at the stage whose bytes it was planned on | `test_classes_compose.py` (RepairLast), `tree_verify.py check` | |
| **workflow control flow** | a step that repairs and builds again repeats until a round finds nothing (bounded), repairs a module once, never plans without time to build, never empties a log for a build that does not run, leaves the last round's log for the verdicts | `test_classes_workflow_shell.py` (the real `run:` text under a fake `lake`/`date`/`elan`) | Navier: one repair round was not enough (3 more modules); a log emptied for a build that never ran refuses every importer |
| **infrastructure is not a result** | a transient error (toolchain download) is retried, never read as a verdict | `test_classes_workflow_shell.py` (ToolchainRetry), `test_classes_verify.py` (NeverGotGoing) | 17 minutes and a silent empty cut |
| **a pinned copy drifts** | the four files of the content lint in `scripts/bump/lint/` are byte for byte tengoku's main; a difference of any one file, however small, a file missing on either side, is found by a machine daily (`lint-drift.yml`), with which file and which options / keywords / definitions were added or removed, in ONE issue; a lint that cannot be read is not called drift | `scripts/test-lint-drift.mjs` (`compare` on random in-memory file maps: every small edit of every file; the summary lists the added and removed options exactly; 10 mutants: one file ignored, text trimmed, line endings normalised, JSON compared by value, only lengths, a missing file as same; an offline fixture with 8 missing options through the command line; the reading of tengoku with stubs; the workflow's permissions) | stafford38-formal 2026-10-27: a hand-kept copy was missing 8 options the tree allows, 2,089 of 2,467 entries refused; at the time of writing the pinned allowlist.py and command-keywords.json already differ from tengoku main |
| **a cut proposed from a log** | the modules proposed for a recut are exactly those with an error of their own that the classes A/B/C/E explain, and the cut they make is closed (nothing kept imports a cut module; it is the one `bundle_cut.cut_dir` makes), minimal (a module that fails only on a declaration of a cut module it imports is cascade, never proposed), monotone (a longer log of the same build never un-drops a module), never the whole library (refused, nonzero status), and the same bytes whatever the order of the log's lines; an error it cannot explain is the residual and no recut starts; a log line quoted as evidence cannot write a workflow command | `test_propose_cut.py` (random import DAGs x random failing modules x noise, against an oracle by index order and a declarative one; the cut compared with `bundle_cut.cut_dir`; 5 mutants: cascade proposed, importers ignored, nothing stops dropping everything, log-order dedupe, D taken for explained), `test_autocut_workflow.py` (permissions, pins, the real `run:` text under a fake `gh` over a real bundle) | stafford38-formal baseline 2026-10-28: 365 of 436 modules dropped, by a person reading `explain_ejection.py` and passing `drop=` by hand |
| **a round that did nothing is not another round** | a build round (not the first) that adds fewer than `min_progress` modules (default 1) to the round before it is not followed by another: the chain ends with an `::error::` holding the numbers, and ONE issue ("setup <key>: build round made no progress") is opened or updated by a job that holds `issues: write` and runs none of the library's code; a round without a count to compare with is not judged | `scripts/test-setup-plan.mjs` (`roundProgress` against an independent statement of the rule on 20,000 random rounds, the boundaries, 5 mutants), `scripts/test-setup-workflows.mjs` (the real `run:` text of build-gate under a fake `gh`, on boundary and random rounds, against `roundProgress`, 7 mutants; the permissions of each job) | flt-anthropic (30,662 modules): three build rounds of 5 hours exported nothing and a person found it by reading the logs |
| **a repair edits only what it names** | the mechanical pass's text repairs (the author's `#print`/`#check` lines and unlisted linter options taken out; an attribute line repeated at the junction of prefix and entry dropped) remove whole inert lines (or, for `set_option linter.X v in`, exactly that phrase; for `#guard_msgs … in`, only its own line, never what it wraps), nothing else: every output line is an input line in order except the one edited by a phrase removal, no line that is not inert is lost or added (counted with multiplicity), a text with nothing inert comes back byte for byte, a second application changes nothing, a command-looking line in a comment or a string is never read as a command, allowed options and non-linter options stay, and the repair never creates a refusal; the lint it asks is the one the bundle lane runs, read from the pinned allow-list files | `test_inert_commands.py` (random texts from the constructs that matter, 4 mutants: comments read as code, an empty allow-list, indented commands taken, and the unmutated code must pass), `scripts/test-lean-repairs.mjs` (the junction on random prefixes and entries; the lint; the bridge keeps no copy and awaits every use) | stafford38-formal 2026-10-27: 2,089 of 2,467 entries refused for `#print axioms` and the like without a compile, 54 for a repeated `@[simp]` that marked the file's prefix broken, 8 options missing from a hand-kept copy of the lint |
| **a vendored dependency is exactly what is reached, under a licence that allows it** | the code a library imports from the other Lake packages it requires is copied into it: exactly the modules reached through imports (random package graphs against an oracle), at their module paths, byte for byte; never Lean or the seeded libraries; only from a package whose licence reads as Apache-2.0, MIT, BSD-2/3, CC0 or Unlicense, and whose module headers do not claim a licence that is not permissive (a package in a subdirectory is licensed by its own file when it has one, never by the repository's instead, and a licence file that is a link out of the package counts for nothing; an unlicensed or copyleft package is refused and what imports it stays unresolved); never a module that declares or uses what runs code at compile time or trusts the compiler (`unsafe`, `initialize`, `elab`, `run_cmd`, `@[extern]`, `@[implemented_by]`, `native_decide`, `IO.Process`, read from code, not comments or strings); never a checkout that is not at the commit the manifest pins; a missing package is fetched only from https://github.com/ at a full commit (also one that only another package imports, found on a later pass), and a failed fetch leaves nothing behind; nothing in a third-party checkout can make the tool read or delete outside it (symlinked subDirectory or file, a marker with `..` or absolute paths; the marker lives beside the library, never inside it); never over a different file the library has, never choosing between two packages that both have a module; a second run changes nothing and keeps the provenance; the step sits after `lake update` and before the imports are read | `test_vendor_deps.py` (Basics, Closure on random graphs, Lifecycle, Safety, Fetch, Wiring, 5 mutants: no licence check, seeded libraries copied, empty permissive list, no code reading, any checkout trusted) | stafford38-formal 2026-10-28: the required package algebraic-analysis was downloaded and never built, 20 of 34 root failures were its imports, 365 of 436 modules were lost with them |
| **nothing moves under a run** | nothing a workflow installs or runs on changes between two runs unless a commit changes it: actions at full commits, `npm install -g` and `pip install` at exact versions (the Claude CLI that translates), a script piped into a shell fetched at a full commit, no `@latest`, the heavy workflows (setup-*, bump-*, translate*) on a concrete runner image (`ubuntu-26.04`, not `ubuntu-latest`); and the setup record names the tools that produced it (Lean, Lake, elan, lean4export commit and the patch it was BUILT with, node, runner image), so a difference between two runs has an explanation on file; a cached lean4export built with another patch than the script now has is rebuilt from a fresh clone. EXCEPTIONS, not covered: the elan binary (the pinned installer script downloads `releases/latest`; `tools.elan` records which one ran), `apt-get install` (the image's distribution version) and each library's own toolchain | `scripts/test-workflow-pins.mjs` (the scanner on 300 random workflow texts with injected violations, including commands continued with a backslash and runners given by an expression, one mutant per rule, the real workflows), `scripts/test-setup-tools.mjs` (the tools asked through a stand-in, merged across shards on random sets), `scripts/test-setup-build.mjs` (the finish phase's record) | `ubuntu-latest` moved from 24.04 to 26.04 between 2026-10-21 and 2026-10-25 under running workflows; the Claude CLI was installed unpinned on every translation; four elan installers came from a branch |
| **memory/time budgets of Gate 2** | a module that cannot be judged does not eat the budget of the ones that can | `test_gate2_driver.py` (skip list, guard poll interval) | Navier: 168 modules unjudged, most of them only because a time budget ran out |
| **only merged code opens pull requests** | the intake opener takes bundles from successful runs of `main` only: a trial run of a feature branch is never the newest bundle of a library | `test_intake_open.py` (`NewestBundles`: feature-branch run ignored though newer, row without a branch ignored, listing asks for `headBranch`) |

KNOWN GAPS (the failure is an honest refusal, never a wrong ship): `open N (a b)`, `open N hiding x` and `open N renaming a → b` are not rewritten, so a name found only in the tree's N through them is not found;
`open … in` inside a term or a tactic block is not a line-start command and is not rewritten; a name the fork and the tree both declare and a THIRD module of the closure declares too is not hidden.

How to add to a class: a new Lean construct -> a `Pattern` in `edit_corpus.py` (it is built by real Lean in CI, nothing else to write); a new log shape -> a generator branch in `Lib.log` of
`test_classes_verify.py`; a new step with a loop -> a scenario in `test_classes_workflow_shell.py` (a module kind in the fake lake: marker line + behaviour); a new way to drop or edit modules in compose ->
an extra argument in `Case.compose` of `test_classes_compose.py` and the invariants already check it.

Mutation check: after writing a class test, break the code the way the old bug did and see the test fail (the commit messages of the PRs that introduced these tests list the mutants tried).
